# YTDock 下载设计规格

状态：待实现  
范围：独立 Python CLI，第一版支持 macOS。

## 1. 目标

提供简单的 YouTube 单视频下载工具：

1. 在终端输入框粘贴视频 URL。
2. 查看视频信息并选择分辨率。
3. 下载并输出兼容性良好的 MP4。
4. 默认保存到系统 Downloads 文件夹。
5. 支持 Ctrl+C 取消，并删除本次任务的半成品。

不接入现有视频编辑器。

## 2. 技术方案

- Python 作为主开发语言。
- yt-dlp 负责视频信息解析与下载。
- prompt_toolkit 负责终端输入框、选择列表和动态状态显示。
- FFmpeg 负责音视频合并及必要的转码。
- ffprobe 负责成品检查。
- 配置 yt-dlp-ejs 和受支持的 JavaScript 运行时，使用 QuickJS（2026-09-08 按用户要求由 Node.js 改为 QuickJS；发布包固定 2026-06-04）。
- 使用独立工作进程执行下载和后处理，主进程负责 UI、取消与清理。
- 使用结构化参数启动子进程，不通过 shell 拼接命令。
- yt-dlp 项目：https://github.com/yt-dlp/yt-dlp

启动时检查依赖。缺少依赖时显示明确的安装提示，不自动安装系统软件。

## 3. 第一版范围

支持：
- YouTube 普通视频和 Shorts。
- 单视频 URL。
- 分辨率选择。
- 下载、合并、必要转码、成品检查。
- 下载进度和取消清理。

暂不支持：
- 批量下载或任务队列。
- 播放列表、频道下载。
- 直播及尚未开始的首播。
- 登录、浏览器 Cookie 导入。
- 字幕、封面、单独音频导出。
- 下载历史及断点续传。

带播放列表参数的视频链接只处理当前视频。
纯播放列表或频道链接明确拒绝。

同一用户同时最多运行一个下载任务；第二个实例不得启动并行任务。

## 4. 交互流程

### 4.1 输入 URL

启动命令为 `ytdock`。

显示类似现代交互式 CLI 的带边框输入框：

    YTDock

    ╭────────────────────────────────────────────╮
    │ 粘贴 YouTube 视频 URL…                     │
    ╰────────────────────────────────────────────╯
    Enter 继续 · Ctrl+C 退出

支持粘贴、光标移动和常规文本编辑。
去除输入首尾空白；空输入不提交。
一次输入多个 URL 时提示只支持一个视频。

### 4.2 解析视频

提交后显示“正在获取视频信息…”。
解析阶段使用活动指示器，不显示虚假百分比。

成功后显示：
- 标题。
- 时长。
- 实际可用的分辨率及帧率。
- 预计文件大小（可获取时）。
- 是否需要转码。
- 输出目录和格式。

获取失败时显示易懂的错误信息，允许重新输入。

### 4.3 选择分辨率

示例：

    示例视频 · 12:34

    选择分辨率
      2160p · 30fps · 需要转码
      1440p · 30fps · 需要转码
    ❯ 1080p · 30fps · 推荐
       720p · 30fps
       480p · 30fps

    输出：系统 Downloads
    格式：MP4 · H.264 + AAC
    ↑↓ 选择 · Enter 下载 · Esc 返回

规则：
- 只显示实际可下载且符合本工具处理能力的选项。
- 按分辨率降序排列。
- 默认选中不超过 1080p 的最高可用分辨率。
- 如果所有选项均高于 1080p，默认选中最低可用分辨率。
- 不把竖屏视频强制转换为横屏；显示实际宽高。
- 同一分辨率存在不同帧率时，明确区分。
- 大小未知时显示“大小未知”；估算值标记为“约”。
- 需要转码的选项提前标明“需要转码，耗时较长”。
- Enter 直接开始当前选择的下载，不再额外确认。

## 5. 输出格式

“标准 MP4”定义为：
- 容器：MP4。
- 视频编码：H.264。
- 视频像素格式：8-bit yuv420p。
- 音频编码：AAC。
- 无音频源保留无音频，不生成静音轨。
- 保留所选源流的实际分辨率、宽高比和帧率。
- 不放大视频，不额外补帧。
- 输出使用 faststart。
- 第一版使用 SDR 源；仅有 HDR 源时提示暂不支持。

格式选择：
1. 在用户选定的分辨率和帧率内，优先选择符合输出要求的源流。
2. 视频或音频已兼容时直接复制对应流。
3. 不兼容的流才进行转码。
4. 视频转码默认使用 libx264、CRF 20、preset medium。
5. 音频转码默认使用 AAC、192 kbps。
6. 不得静默降低用户选定的分辨率。
7. 所选格式失效时重新获取选项，让用户重新选择。

不得仅修改扩展名，也不得把“MP4 容器”等同于“H.264 + AAC”。

## 6. 进度显示

按实际处理顺序显示当前阶段：
- 下载视频。
- 下载音频。
- 合并。
- 转码（需要时）。
- 检查文件。
- 保存完成。

音视频已包含在同一源文件时，显示“下载视频”，不展示不存在的音频下载阶段。

下载阶段显示：
- 百分比。
- 已下载大小 / 总大小（可获取时）。
- 下载速度（可获取时）。
- 预计剩余时间（可获取时）。

示例：

    下载视频  12.3%  · 24.6 / 200 MB · 5.2 MB/s · 剩余 00:34
    下载音频  100%  · 8.4 / 8.4 MB
    合并中…
    检查文件…
    已保存：/实际系统下载目录/示例视频 [视频ID].mp4

百分比格式：
- 精确为 0 时显示 `0%`。
- 阶段完成时显示 `100%`。
- 其余值保留一位小数，例如 `0.1%`、`5.0%`、`12.3%`、`99.9%`。
- 整数部分不补前导零，例如使用 `5.0%`，不使用 `05.0%`。
- 很小的非零进度允许显示 `0.0%`。
- 阶段未完成时，即使四舍五入会得到 100，也最多显示 `99.9%`。
- 总量未知时显示已下载大小和速度，不伪造百分比。
- 总量为估算值时明确标记“约”，允许估算修正。

显示规则：
- 百分比属于当前阶段，不把视频下载完成当作整个任务完成。
- 视频和音频分别显示各自进度。
- 合并、检查等无法可靠计算进度的阶段使用活动指示器。
- 转码可依据 FFmpeg 已处理时间和视频时长显示阶段进度。
- 原地刷新状态，不持续刷出新行。
- 控制刷新频率，建议每秒不超过 10 次。
- 完成成品检查和最终保存后，才显示“下载完成”。

## 7. 输出目录与文件名

- 通过系统接口获取当前用户的 Downloads 文件夹。
- 不使用当前工作目录作为隐式回退。
- 目录不存在或不可写时，明确报错。
- 默认文件名：`视频标题 [视频ID].mp4`。
- 清理文件名中的非法字符并限制长度。
- 文件名不得包含路径穿越片段。
- 重名时依次添加 ` (1)`、` (2)` 等后缀。
- 不覆盖或删除已有文件。
- 最终只保留成品 MP4，不额外输出元数据、封面或字幕文件。

## 8. 临时文件与取消

每个任务在 Downloads 下创建独立的隐藏临时目录。
本次下载的片段、音频流、视频流及转码文件均写入该目录。

Ctrl+C 行为：
- 输入或选择阶段：直接退出。
- 解析、下载、合并、转码或检查阶段：
  1. 显示“正在取消并清理…”。
  2. 停止任务及其全部子进程。
  3. 等待进程退出；超时后终止仍存活的进程。
  4. 删除本次任务的临时目录。
  5. 显示“已取消，临时文件已清理”并退出。
- 重复按 Ctrl+C 不得跳过清理流程。
- 取消退出码为 130。

清理规则：
- 不只删除 `.part`，还须清理已下载的独立流、片段及后处理文件。
- 只能删除确认属于本工具、本次任务的文件。
- 清理失败时明确报告残留路径，不得声称已清理成功。
- 网络失败或后处理失败也执行清理。
- 强制杀进程或断电无法保证即时清理；下次启动清理确认已失效的本工具临时任务。
- 不删除其他仍在运行的任务目录。
- 已成功发布的成品不因后续 Ctrl+C 被删除。

## 9. 成品检查与发布

下载及后处理结束后：
1. 确认文件存在且非空。
2. 使用 ffprobe 检查容器、视频编码、像素格式、尺寸、帧率和音频编码。
3. 检查时长与源信息合理一致。
4. 进行解码检查，确认没有截断或明显损坏。
5. 检查通过后，以不覆盖已有文件的方式发布到最终路径。
6. 清理临时目录。
7. 显示最终路径并返回 URL 输入框。

最终发布在同一文件系统内进行，避免用户看到半成品。
发布时再次处理文件名冲突，不能只依赖下载前的重名检查。

## 10. 错误处理

为以下情况提供明确提示：
- URL 无效或不受支持。
- 视频不存在、私有、需要登录或地区不可用。
- 没有支持的可下载格式。
- 网络超时或连接中断。
- 下载地址或所选格式失效。
- 磁盘空间不足。
- Downloads 不可写。
- FFmpeg 或其他依赖缺失。
- 合并、转码或成品检查失败。

瞬时网络错误允许有限次数重试，例如最多 3 次。
重试期间仍可 Ctrl+C 取消。
普通错误清理后返回输入框。
默认不显示 Python 堆栈，不在日志中输出 Cookie、令牌或带签名的媒体下载地址。

## 11. 验收标准

- 可以通过输入框粘贴单个 YouTube URL。
- 可以选择实际可用的分辨率和帧率。
- 默认选项遵循不超过 1080p 的规则。
- 进度正确显示 `0%`、`5.0%`、`12.3%`、`99.9%` 和 `100%`。
- 总大小未知时不显示虚假百分比。
- 下载阶段达到 100% 后，仍正确显示后续处理阶段。
- 成品为符合约定的 MP4，且有音频源不会意外丢失音频。
- 高分辨率需要转码时提前标明。
- 默认保存到系统 Downloads，重名不覆盖。
- 在下载视频、下载音频、合并、转码和检查期间取消，均停止全部子进程并清理半成品。
- 下载失败、磁盘写入失败或检查失败时，不留下伪装成成品的文件。
- 已存在文件和已发布成品不会被取消清理误删。
- 带播放列表参数的链接只处理当前视频。
- 纯播放列表、频道和直播链接被拒绝。
- 第二个实例不能启动并行下载。
- 下载成功后可以继续输入下一个 URL，但不存在任务并发或队列。


## 12. 独立分发（2026-09-08 补充）

- 提供 `./package.command` 一键构建可分发 ZIP，不安装系统软件。
- 包内包含 Python、yt-dlp/ejs、QuickJS 和 UI；FFmpeg/ffprobe 改为外部依赖，详见 external-ffmpeg.md。
- 固定原生源码版本和校验值，附带第三方许可证、对应源码和构建脚本。
- 按构建机架构生成 macOS 14+ 原生包；当前验收架构为 arm64。
- 支持双击 Install.command、Start.command、Uninstall.command，并提供命令行安装/卸载。
- 默认按用户安装，无需 sudo；原子升级、失败回滚，命令冲突不覆盖。
- 卸载保留下载的视频，不删除其他工具的文件；活动任务阻止升级或卸载。
- 冻结后的工作进程通过同一可执行文件启动，取消仍终止整个进程组。
- Apple Developer ID 签名和公证是独立发布步骤；未公证的产物须明确标注。

执行 [压缩模式计划](compression.md)，与下载模式共享单实例、外部 FFmpeg、工作进程、取消清理和安全发布。输入页 Tab 切换，保留未提交 URL；输出保留实际分辨率和帧率。具体支持边界与验收记录见 README 和 implementation.md。
