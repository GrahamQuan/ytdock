# 导出 Mac 快速查看兼容 MP4

状态：已实现。下方记录了自动化校验、当前 Mac 的系统媒体测试和待完成的 Finder 验收。

用户选择一个本地视频，导出一份独立的 `<原文件名>.preview.mp4`。目标是在支持范围内的 Mac 上，从 Finder 选中文件并按空格即可看见首帧、播放视频和拖动进度。首版面向常见的 MP4、MKV、MOV，包括 iPhone 和安卓相机、手机录屏产生的文件。根据实际容器、轨道和可用解码器判断输入能力；同为 MP4 的两个文件可以采用完全不同的编码。

## 使用方式

在 YTDock 的「Mac 预览」页输入视频路径，确认所选音轨和输出目录后开始导出。检测到强制字幕时可以选择烧录。交互界面将成品保存到系统下载目录。

在项目根目录也可以直接运行以下命令，在源文件旁生成副本。重名时自动追加序号。命令行和交互界面使用相同的转换与校验逻辑。

```sh
uv run ytdock --mac-preview "/路径/手机录像.mov"
uv run ytdock --mac-preview "/路径/影片.mkv" --burn-forced
```

## 官方依据与兼容范围

- Apple 的 Finder 指南说明了空格快速查看的入口。查阅到的指南没有列出按 Mac 型号和 macOS 版本细分的完整视频参数表。发布前需要列明实测的最低系统版本、机型和芯片。[Apple 快速查看指南](https://support.apple.com/guide/mac-help/preview-a-file-mchlgtd_prev01/mac)
- QuickTime Player 导出时将 H.264 列为「更佳兼容性」选项。该指南描述的是 MOV 导出，可作为选择 H.264 的依据。[Apple QuickTime Player 导出指南](https://support.apple.com/zh-cn/guide/quicktime-player/qtp20e395859/mac)
- Apple 的 HLS 制作规范建议，为扩大兼容范围，至少提供一档 H.264 High Profile、Level 4.1 或以下的视频，并列出 AAC 立体声的设备兼容情况。本方案借鉴其中的编码建议，采用适合本地文件的 MP4 封装。1080p、30 fps 是本产品预览副本的保守上限，Finder 的实际能力需要实测。[Apple HLS 制作规范](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html)
- HEVC 的可播放性也受机型、分辨率和帧率影响。HEVC 手机原片纳入输入范围，统一导出下述 H.264 预览档。[Apple HEVC 兼容性说明](https://support.apple.com/zh-cn/116944)

## 输出规格

| 项目 | 预览副本要求 |
|---|---|
| 容器 | 单文件、非分片 MP4，视频标记 `avc1`。使用 `+faststart` 将索引置于媒体数据之前，便于尽早读取。[FFmpeg 封装文档](https://ffmpeg.org/ffmpeg-formats.html) |
| 视频 | 一条 H.264/AVC 主视频轨，8-bit、4:2:0（`yuv420p`）、逐行扫描。新编码采用 High Profile，最高 Level 4.1。编码时约束实际码流，包括参考帧、峰值码率和缓冲区；仅改写 Level 标签不足以满足要求。 |
| 显示尺寸 | 应用旋转、镜像和源像素宽高比后，按显示比例缩入长边 1920、短边 1080 的范围，小视频不放大。输出偶数宽高、方形像素。竖屏上限为 1080 × 1920；奇数尺寸可少量补边，避免拉伸或裁掉内容。 |
| 时间线 | 最高 30 fps，保留符合上限的原始播放节奏，包括 23.976、25 和 29.97 fps。高帧率按显示时间戳降采样，如 59.94 → 29.97 fps。保持播放时长和音视频相对起点。 |
| 色彩 | SDR BT.709、有限范围，像素转换与输出的色域、传递函数、矩阵和范围标签一致。HDR 执行适配其格式的色调映射。 |
| 音频 | 有声视频保留一条 AAC-LC 音轨：单声道保持单声道，立体声保留，多声道按布局混为立体声。保留 44.1 或 48 kHz，其他采样率转 48 kHz。无声视频保持无音轨。 |

## 探测与转换

1. 使用 ffprobe 读取真实容器、各轨道及其默认标记、编码参数、显示矩阵、色彩信息和时间戳。排除封面图，优先选默认主画面与音轨。MKV 有多音轨时显示所选语言和轨道；检测到强制字幕时提供烧录选项。烧录需要重新编码视频。
2. 按轨道决定是否复制。视频与音频均满足目标且无需滤镜时只重新封装；已满足全部封装与轨道要求的 MP4 可直接复制为预览副本。仅音频不合规时只转音频，例如 H.264 + DTS 的 MKV；仅视频不合规时保留合规音频，例如 AV1 + AAC-LC 的 MP4。无法确认码流符合目标时重新编码。
3. 对需要转换的轨道检查本机 FFmpeg 的解码器、编码器和所需滤镜。文件损坏、加密、无法解码或缺少特定转换能力时，提示具体文件、轨道或能力。写入临时文件，验证成功后发布，沿用现有的重名保护和取消清理机制，保留原件。

### 手机素材的特殊处理

- **竖拍和前置相机**：读取完整显示矩阵，包括镜像。将变换应用到像素一次，并清除已应用的方向信息，再验证最终显示宽高。用带文字或左右方向标记的样片检查镜像。
- **HDR 与 10-bit SDR**：分别识别 HLG、PQ（HDR10 / HDR10+）、Dolby Vision 和 10-bit SDR。依据传递函数、色域和 Dolby Vision 配置选择处理路径；能可靠解释的 HDR 转为 SDR，并移除失效的 HDR 元数据。缺少必要色彩信息或无法解释 Dolby Vision 配置时给出明确原因。单改像素格式或色彩标签会造成错误亮度或颜色。[Android 相机 HDR 格式表](https://developer.android.com/media/camera/camera2/hdr-video-capture) · [Apple HDR 元数据说明](https://developer.apple.com/av-foundation/High-Dynamic-Range-Metadata-for-Apple-Devices.pdf)
- **录屏与慢动作**：可变帧率录屏按逐帧时间戳处理，尤其检查长静止画面后的音画同步。120/240 fps 素材按输入的播放时间线导出。依赖「照片」编辑结果的慢动作区间或电影效果，请使用已渲染的分享版本作为输入。[Apple 电影效果视频编辑说明](https://support.apple.com/en-euro/guide/iphone/iph5e602f6d6/ios)

## 与现有实现的衔接

可复用本地文件身份检查、主轨选择、外部 FFmpeg 调用和完整解码校验。预览导出需要独立的输出参数与验证预期：

- 本地压缩的输入检查目前会拒绝 HDR、显示矩阵、隔行和奇数尺寸。预览模式应对可处理的输入安排相应变换，包括对隔行素材去隔行，并在开始前说明无法处理的原因。[本地压缩实现](../../src/ytdock/compression.py) · [已有压缩规格](../compression.md)
- 下载流程的视频复制条件主要检查 H.264 和像素格式，音频主要检查 AAC。预览模式需额外核对上表中的尺寸、帧率、色彩、Profile/Level、AAC profile、声道及采样率。现有验证器会比对源帧率和像素宽高比；预览模式应根据转换计划核对输出，同时对照源时间线验证时长和同步。[媒体处理与验证](../../src/ytdock/media.py)

## 验收

遇到无法预览的文件时，可先用同目录的 [inspect_video.py](inspect_video.py) 生成 JSON 诊断报告。在项目根目录运行以下命令；省略路径则可按提示从 Finder 拖入文件。反馈时附上报告、Finder 按空格后的表现，以及 QuickTime Player 能否播放同一文件。

```sh
python3 specs/mac-video-preview/inspect_video.py "/Users/你的用户名/Movies/我的视频.mp4"
```

每个成功样片先用 ffprobe 核对输出规格并完整解码音视频，再在最低支持配置与一台当前 Mac 上实测 Finder 空格预览。记录机型、芯片、macOS 版本、首帧能否出现、能否播放及拖到中段和片尾。用有声样片核对开头和片尾的音画同步。自动解码通过只完成文件校验，Finder 实测单独记录。

| 样片 | 重点检查 |
|---|---|
| 实际无法按空格播放的 MP4 | 记录原文件在目标 Mac 上的表现及轨道信息，在同一台 Mac 上比较转换后的首帧、播放和拖动。 |
| 已合规的 H.264 + AAC-LC MP4 | 走复制路径，保留原画质和音质；失败或重名时不覆盖原件。 |
| 带封面、多音轨和强制字幕的 MKV | 主画面、语言和字幕符合选择；仅音频不合规时复制视频。 |
| iPhone 竖屏 Dolby Vision MOV、安卓 HLG/HDR10 MP4 | 分别检查竖屏方向、镜像、肤色和高光；用已知方向和 SDR 参考画面比对。 |
| 可变帧率录屏、4K60 和 120/240 fps 素材 | 降帧后时长、片尾同步和播放速度正确，文件满足尺寸和帧率上限。 |
| 无声竖屏、奇数尺寸、非方形像素和隔行样片 | 无声文件可播放；画面比例正确，无意外裁切或梳齿。 |
| 损坏文件、无法处理的 Dolby Vision 配置、中途取消 | 提示具体原因，不发布残缺副本，清理临时产物。 |


### 已执行的验证

- 在 MacBook Pro（MacBookPro17,1，Apple M1）、macOS 14.8.4、FFmpeg 7.1.1 上，将一段带声音的 60 fps MKV 导出为 30 fps MP4。系统 Quick Look 成功生成缩略图。AVFoundation 判定文件可播放，识别一条音轨，并在约 0.03、6.00 和 11.90 秒成功读取画面。
- 合成样片覆盖 HLG、PQ、4K60、240 fps、可变帧率、竖屏、水平镜像、奇数尺寸、非方形像素、隔行和无声视频。对已合规的 MP4 比较导出前后 H.264 与 AAC 码流的 SHA-256，两轨分别一致。
- 自动测试覆盖 MKV 默认语言音轨、强制文本字幕烧录、文件重名、损坏输入与取消清理。Dolby Vision 配置判断使用模拟探测信息。对 profile 8 的 HDR10 或 HLG 兼容基础层按其传递函数处理；其他未经验证的配置报告错误。普通 8-bit YUV 输入缺少颜色标签时按 SD/HD 尺寸推定；高位深或 HDR 缺少必要信息时报告错误。
- 待验收项包括实际无法预览的 MP4、真实手机 Dolby Vision 画面与 SDR 参考的对照，以及 Finder 窗口内的播放、拖动和听感同步。当前环境未启用界面自动化权限。其他 macOS 版本和机型的兼容范围仍需实测。
